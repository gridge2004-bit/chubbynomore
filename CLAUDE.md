# chubbynomore

Cash-pay telehealth marketing + intake site for GLP-1 weight-management care.
TanStack Start (SSR) + React 19 + Tailwind v4 + Supabase, built and hosted via
Lovable, deployed on Netlify.

**This file exists so you do not have to re-explore the repo.** Read it first and
go straight to the file you need.

## Where things live

## Landing page modules (`src/components/home/`)

The homepage was one 2,204-line file. It is now split so an edit touches ~100
lines instead of the whole page. **Do not re-merge it, and do not read the whole
directory** — open only the section you are changing.

- `content.tsx` — all copy, pricing data, types and section config. Most
  copy/price changes are a one-file edit here and nothing else.
- `Nav.tsx` — `PromoBanner`, `PillButton` (shared), `Nav`
- `Hero.tsx`, `MedicalTeam.tsx`, `Testimonials.tsx`, `StickyMobileCTA.tsx`
- `Story.tsx` — `SwitchingCare`, `WhyChoose`, `HowItWorks`
- `Trust.tsx` — `TrustMarquee`, `WeightLossScale`, `TrustedCare`
- `EmotionalTransformation.tsx` + `HeroTile.tsx`
- `MedicationOptions.tsx` — catalogue section, composed of
  `DetailedProductCard.tsx` → `PlanCompare.tsx`, plus `MedicationRow.tsx` and
  `MedicationInfoPanel.tsx`
- `Qualify.tsx` — `WhoQualifies`, `WhoNotFor`
- `FAQ.tsx`, `Footer.tsx` (`FinalCTA` + `Footer`)

## Conventions

- Imports use the `@/` alias for `src/`. Landing sections import siblings
  relatively (`./content`).
- Brand colours are inline Tailwind arbitrary values: navy `#103942`, teal
  accent `#42D1C3`, light grey `#F5F5F7`. There is no theme token layer.
- `*.server.ts` runs server-only; `*.functions.ts` holds TanStack server
  functions. Do not import a `.server.ts` module from client code.
- Images in `src/assets/`. A `<name>.asset.json` sidecar is a Lovable-hosted
  asset — import it and use `.url`. Plain `.jpg`/`.png` imports are bundled.

## Regulatory guardrails — read before editing marketing copy

This is health advertising for compounded, prescription-only medication. Copy
changes are a compliance surface, not just a conversion surface.

- Never state or imply guaranteed results, guaranteed approval, or a guaranteed
  prescription. Keep "not everyone qualifies" style qualifiers intact.
- Compounded medications are **not FDA-approved**; keep that qualifier wherever
  compounded products are named.
- Do not add testimonials, star ratings, statistics, credentials or trust badges
  unless the user supplies verified, consented, substantiated data. The
  `showTrustedCareSection` / `testimonialsEnabled` flags in `content.tsx` are
  deliberately `false` — leave them off unless explicitly told otherwise.
- Do not name brand drugs (Ozempic, Wegovy, Mounjaro, Zepbound) as products
  offered. They were deliberately removed; unused brand assets still sit in
  `src/assets/`.

## Commands

```
bun install
bun run dev      # vite dev
bun run build    # vite build
bun run lint     # eslint
bun run format   # prettier --write
```

Note: `bun run lint` currently reports ~1,100 pre-existing `prettier/prettier`
errors across the repo. That is existing debt, not something your change caused.
Do not run a repo-wide `--fix` as part of an unrelated change — it would bury
the real diff. Check that your change does not *increase* the count.

## Working in this repo

- It is connected to **Lovable**. Never force-push, rebase, amend or squash
  pushed commits — it rewrites history on Lovable's side and the user loses
  project history. Keep the connected branch in a working state.
- `src/routeTree.gen.ts` is generated by the TanStack router plugin. Never edit
  it by hand and never read it for information.
- `bun.lock` resolves through Lovable's private npm registry. Do not regenerate
  it outside Lovable — a plain `npm`/`bun install` against public npm will
  produce a lockfile that breaks the deploy.
